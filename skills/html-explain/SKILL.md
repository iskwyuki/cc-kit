# 説明ドキュメント（Artifact）

## 文章

説明内容と日本語表現を補うため、次のスキルの併用を推奨する。

- `explain`：概念や仕組みを説明するときの用語定義、説明の粒度、構成
- [`japanese-tech-writing`](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)：日本語の技術文書、記事、解説文の構成と文章規範
- [`cognitive-rhythm-writing`](https://gist.github.com/k16shikano/eb2929f13ed19c97188393d297be8432)：読み物としての緩急が必要な長文の文章規範

いずれも推奨スキルであり、必須依存ではない。

## 成果物

既定は **Claude Artifact** とする。ローカルの HTML ファイルも同じソースから作れる。

作成前に `artifact-design` スキルを読み込む。ハーネスが Artifact を書く前の必須手順として要求している。その上でこのデザインシステムを適用する。

手順は次のとおり。

1. `templates/document.src.html` を写して `{yyyymmdd}-{内容を表すケバブケース}.src.html` として保存する。保存先が指定されている場合は従う。指定がなければ現在の作業ディレクトリへ置く
2. 内容を書く。ソースには骨格タグ（doctype / html / head / body）を書かない
3. `scripts/build.sh <src>` でビルドする。CSS と JavaScript の実体が流し込まれた `.html` ができる
4. Artifact ツールでその `.html` を publish する。絵文字の favicon が必須。`<title>` がタブ名とギャラリー名になる

既存ファイルの更新では名前を変えない。`.src.html` を直し、ビルドし直し、**同じファイルパスで** publish すると同じ URL が更新される。

ローカルの単体ファイルが必要な場合は `scripts/build.sh --standalone <src>` を使う。骨格タグを付けた通常の HTML を出力する。ブラウザで直接開けて、PDF 化はユーザーから明示的に依頼された場合だけ `render-pdf.sh` を実行する。

個別の文書管理システム、メタデータ、Viewer、公開先に関する規則は、このスキルを参照する上位スキルの指示に従う。

## Artifact の制約

- **外部ホストへの通信は CSP で遮断される。** CDN の script / stylesheet / 画像 / fetch はすべて失敗する。唯一の例外が Google Fonts で、字体だけは従来どおり読み込める
- そのため CSS と JavaScript はページ内に実体として持たせる。`build.sh` がこれを行う
- **骨格タグを書かない。** publish 時に doctype / html / head / body で包まれる。ソースに書くと壊れる。`build.sh` は見つけたらエラーで止める
- ビューアのサンドボックスがページ発のダウンロードを遮断するため、`<a download>` や JavaScript による保存は機能しない
- 表・図・コードなど横に広い要素は、それぞれの `overflow-x: auto` の中でスクロールさせる。ページ本体を横スクロールさせない
- **数式を含むページは初回表示が遅い。** 約 2.2MB の MathJax を解析する間、ビューアは空白のまま、あるいは本文が途中まで描かれた状態になる（実機で十数秒を観測）。数式が無い文書では `<!--MB:MATH-->` を省くこと。省けば出力は約 150KB に収まり、この待ちは発生しない

## ビルドのマーカー

ソースに置いたマーカー行が、ビルド時にファイルの中身へ置き換わる。

| マーカー | 差し込まれるもの | 目安のサイズ |
|---|---|---|
| `<!--MB:CSS-->` | `design-system/document.css` | 約 15KB |
| `<!--MB:HLJS-->` | Highlight.js と初期化 | 約 125KB |
| `<!--MB:MATH-->` | 数式コピー用 JS と MathJax | 約 2.1MB |

**必要なマーカーだけ書く。** 数式が無い文書で `<!--MB:MATH-->` を省けば、MathJax の約 2.1MB はページに入らない。

`<!--MB:HEAD-->` と `<!--MB:/HEAD-->` で囲んだ範囲は、`--standalone` のとき `<head>` の中へ入る。Artifact モードではマーカー行が取り除かれるだけになる。

## デザインシステム

作成前に `design-system/component-samples.html` を確認する。部品の見本は `design-system/document.css`、数式コピー機能は `design-system/math-copy.js` を正とする。

主要規則は次のとおり。

- 配色はすべて `document.css` の設計トークンを経由する。個々の部品に色をベタ書きしない
- 画面はダーク固定。緑みのある濃灰の地に、部品は地よりわずかに明るい面、細い罫線、角丸を基本とする（印刷時はオフホワイト `#FAF9F6` + 白地 + 黒罫線に戻る）
- 自然言語は Ubuntu Sans と Noto Sans JP、コード・URL・日付は Ubuntu Mono を使う
- 有彩色はリンク青とアクセント赤に限定する
- 赤い強調は原則として 1 ページ 1 箇所までとする
- シンタックスハイライトとコード差分の色は、意味を区別する機能色としてこの制限の対象外とする
- 余白は上下左右の均衡を保つ
- 引用は `.mb-quote` を使い、原文と訳文を同じ文字サイズ・色で上下に並べる
- `.mb-chip` は並列の固有名や分類名の列挙にだけ使う
- 絵文字や矢印文字を図記号として使わない。必要な記号はインライン SVG で描く
- 表は短い対応関係に使い、3 列までを基本とする
- **`th` は列見出し（先頭行）にだけ使う。** `th` は下端だけ濃い罫線が引かれる設計なので、行ごとに `th` を使うと左列だけ全行に濃い線が入り、濃淡が意味を失う。行見出しは `td` にする
- 行見出しのセルには `.mb-rowlabel` を付け、語中の折り返しを防ぐ
- コード差分は `pre.mb-diff` を使い、変更理由を散文で説明してから必要な断片を示す
- ページ固有の `<style>` は図の配置調整など最小限にとどめる

## 配色（ダーク固定）

画面はダーク固定とする。OS 設定への追従やテーマ切替の分岐は持たない。意図的に単一の見た目へ決め打っている。

- 配色はすべて `document.css` の設計トークンを経由する。個々の部品に色をベタ書きしない
- **純黒に純白を載せない。ただしコントラストを下げて避けてはいけない。** 地は緑みのある濃灰、文字は純白ではない淡色にしたうえで、本文のコントラスト比は 15.4:1 を保っている。両側を灰へ寄せて詰めると輪郭が甘くなり、読んでも頭に入らない文章になる。ページ固有の色を足すときも同じ考え方で選ぶ
- **トークンの定義は 2 箇所だけ。** 素の `:root`（画面用のダーク）と、`@media print` の中の `:root`（紙用のライト）
- **色を足すときは必ず両方に書く。** 画面側だけに足すと、印刷時にダークの値が残り、白地に白い文字が出て読めなくなる
- `body` にはトークン由来の背景色を明示する。透過のままだとビューアの地の色を借りてしまう
- **ページ内にテーマ切替ボタンを置かない。** ページが自前の背景色を塗るため、Artifact ビューアのテーマ操作はこのページには効かない。共有した相手の画面でも常にダークで表示される

ページ固有の `<style>` で色を足す場合も、必ずトークンを参照する。生の色値を書くと印刷で破綻する。

## 構成とフォーマット

説明対象に合わせて、並置、図解、タイムライン、要約、折りたたみを使い分ける。
一方向の単純な手順を、必要性なくフローチャートにしない。

基本構成は次の順とする。

1. 用語リスト
2. 背景
3. 本論
4. 具体例
5. 補足・限界・関連事項

骨格は 3 カラムとする。`.mb-wrap` の直下に `nav.mb-toc`、`.mb-main`、`aside.mb-glossary` をこの順で置く。DOM の順序がそのままカラムの順序になる。

```html
<div class="mb-wrap">
  <nav class="mb-toc">...</nav>
  <div class="mb-main">...</div>
  <aside class="mb-glossary">...</aside>
</div>
```

- **目次は左サイドバー**に置く。各 h2 に対応する `id` を付け、`nav.mb-toc` の `<ol>` から参照する
- 用語リストは右サイドバーの `aside.mb-glossary` に置く
- 目次と用語リストはそれぞれ独立したスクロール領域を持つ sticky なサイドバーになる。幅 1200px 以下では用語リストが本文の下へ回り、860px 以下では 1 カラムになる
- h1 とリード文は `.mb-wrap` の外、`.mb-header` と `.mb-lede` に置く
- 専門用語は本文で使う前に 1〜2 文で定義する

## 図

- `.mb-figure` は、画像・SVG などの視覚資料とキャプションを一つにまとめる外枠である。特定の図形や「矢印で結んだ箱」を意味しない
- `.mb-figure-frame` は視覚資料の表示面、`figcaption` は図番号・説明・出所の表示領域として使う
- 原典に重要な図がある場合は、出所を明示して引用する
- 原典の図があるのに模倣図を作らない
- 自作図はインライン SVG とし、アスキーアートを使わない
- 単色の線画を基本とし、`.mb-figure-frame` に載せる
- **SVG の色はトークンを参照するか `currentColor` を使う。** `stroke="black"` のようなベタ書きはダークで見えなくなる
- ノード数が多い場合は縦方向を優先する
- 矢印が交差する構成を避ける
- 単なる直列手順は番号付きの説明として表現する
- **外部の画像 URL は使えない。** 画像は data URI として埋め込むか、インライン SVG で描く

## コード

- `<!--MB:HLJS-->` を置いてシンタックスハイライトを有効にする
- `pre code` には `language-javascript`、`language-python`、`language-html` などの言語クラスを必ず付ける
- ハイライトしないテキストには `language-plaintext` を付ける
- 独自の色付けでコードを装飾せず、`document.css` の `.hljs-*` 規則を使う
- `pre.mb-diff code` には `nohighlight` を付け、差分専用の色と行頭記号を使う

## 数式

- `<!--MB:MATH-->` を置く。MathJax 3 の **SVG 出力（`tex-svg-full`）**が同梱されている
- インライン数式は `$...$`、ディスプレイ数式は `$$...$$` とする
- ベクトルと行列は `\boldsymbol{...}` を使う
- スカラー、添字、集合名は装飾しない
- 名前付きの演算は `\mathtt{...}`、標準 LaTeX コマンドはそのまま使う
- `math-copy.js` により、すべての数式から LaTeX 原文をコピーできる
- ページ側で `window.MathJax` を再定義しない
- 未知のコマンドを別記法へ勝手に置換しない

同梱しているのは `tex-svg-full` で、TeX の全パッケージを内包する。`\boldsymbol` `\color` `\cancel` `\bbox` `\braket` `\verb` `mhchem` `physics` などは遅延読み込みなしで使える。

**ただし `\require{...}` は使えない。** 実行時に任意のパッケージを取りに行くため無効にしてある。CSP 下では遅延読み込みが CDN へ出て遮断される。数式が赤字の生 TeX のまま表示されたら、未定義コマンドを疑う。

CHTML 出力を使わない理由も同じで、CHTML は描画時に MathJax 自身の woff フォントを CDN から取得するため CSP で止まる。SVG 出力はグリフをパスとして描くのでフォントを取りに行かない。

MathJax の右クリックメニューは無効にしてある。数式の LaTeX コピーは `.mb-math-copy` ボタンが担う。なお **Artifact のサンドボックス内ではクリップボード API が制限される場合があり、コピーボタンが無反応になることがある**。

## 印刷と PDF

印刷対応は `document.css` の `@media print` を使う。印刷時は 3 カラムを解除し、用語リストを改ページして末尾に送る。

PDF 化は `--standalone` でビルドしたファイルに対して、ユーザーから明示的に依頼された場合だけ `render-pdf.sh` を実行する。Artifact からは PDF を出せない。
